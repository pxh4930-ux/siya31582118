# 작업 지시서: 김보험 모바일 영업 홈페이지

> 이 문서는 AI 코딩 에이전트에게 전달하는 작업 지시서입니다.
> 이전 대화 내용은 없다고 생각하고, 이 문서만 보고 작업해 주세요.
> (김보험과 소속 회사, 연락처는 강의용 가상 정보입니다.)
>
> - **1~9번**: 초안을 만들고 배포하기까지의 지시입니다. [고정]은 그대로, [가이드]는 방향 안에서 판단해 만듭니다.
> - **10번**: 초안 이후 사용자가 디자인 수정이나 기능 추가를 요청할 때 따르는 규칙입니다.

> **변경 기록**: 홈페이지 주인 이름을 '김보험'에서 **'박시아'**로 변경했습니다(사용자 요청). 이름·이니셜·탭 아이콘 글자(박)·소개 제목·인사말·푸터가 모두 바뀌었고, 이 문서 3-3의 `site.ts`가 현재 내용입니다. 문서 본문 다른 곳의 '김보험' 표현은 초기 작성 당시 이름입니다.

## 0. 작업 원칙 (가장 먼저 읽을 것)

이 문서는 두 가지 수준으로 지시합니다.

| 표시 | 의미 | 해당하는 것 |
|---|---|---|
| **[고정]** | 적힌 그대로 따릅니다 | 기술 스택과 설치 명령, 파일 구조와 이름, `site.ts`의 구조와 문구, 섹션 구성과 순서, 기능과 완료 기준, 색상 값, 접근성 기준, 배포 설정 |
| **[가이드]** | 방향과 기준값 안에서 에이전트가 판단합니다 | 세부 배치, 글자 크기와 간격, 카드·버튼 모양, 장식 요소, 애니메이션 세부 값, 미리보기 이미지 구성 |

[고정] 항목은 초안 이후의 수정·기능 추가(10번)가 이 구조를 전제로 하기 때문에 바꾸지 않습니다. [가이드] 항목은 결과가 조금씩 달라도 괜찮습니다.

1. **[고정] 항목은 바꾸거나 "더 좋은 방식"으로 대체하지 않습니다.**
2. **초안에는 문서에 없는 기능·섹션·버튼·문구를 추가하지 않습니다.** 추가는 초안 완성 후 사용자가 요청할 때 10번 규칙에 따라서만 합니다. (디자인 디테일은 [가이드] 범위 안에서 자유롭게 정합니다.)
3. **문구는 `src/config/site.ts`에만 존재합니다.** 컴포넌트 안에 한국어 문구, 전화번호, 링크를 직접 적지 않습니다.
4. **색상은 4-1의 변수로만 씁니다.** 컴포넌트에 hex 값을 직접 적지 않습니다. (예외는 10-3 표의 위치뿐)
5. **도구의 기본 설정과 이 문서가 다르면 이 문서를 따릅니다.**
6. **문서대로 할 수 없는 상황이면 멈춥니다.** 임의로 해결하지 말고, 무엇이 왜 안 되는지와 선택지 2개를 사용자에게 보여준 뒤 결정을 기다립니다.
7. **8번 "작업 순서"의 단계를 하나씩 진행합니다.** 단계마다 완료 기준을 모두 확인하고, 결과를 사용자에게 보여주고, 확인을 받은 뒤 git 커밋하고 다음 단계로 넘어갑니다.
8. 사용자는 코딩 경험이 없는 보험설계사입니다. 명령을 실행하기 전에 무엇을 왜 하는지 한두 문장으로 쉽게 설명합니다.

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 누구의 홈페이지 | 김보험, 보험설계사 8년차 (든든보험파트너스 소속) |
| 무엇 | 카카오톡으로 링크를 보내면 휴대폰에서 바로 열리는 모바일 웹 명함 겸 소개 페이지 (원페이지) |
| 목적 | 지인 소개나 명함으로 김보험을 알게 된 사람이 신뢰를 느끼고, 부담 없이 상담 연락을 하게 만든다 |

**말투**: 따뜻하고 차분한 존댓말, 과장 없이 담백하게. (초안 문구는 3-3에 모두 확정되어 있으므로 새로 쓰지 않습니다.)

```ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  output: "export",
  images: { unoptimized: true },
  trailingSlash: true,
  // Tailwind CSS 연결 (create-next-app이 만든 설정, 지우지 마세요)
  turbopack: {

        loaders: ["@tailwindcss/turbopack"],
```

## 4. 디자인 명세

### 4-1. 색상 [고정] — `src/app/globals.css`

shadcn/ui가 만든 `:root` 블록에서 아래 변수의 값을 **이 값으로 교체**합니다. 나머지 변수는 그대로 둡니다.

| 변수 | 값 |
|---|---|
| `--background` | `#FAF8F5` |
| `--foreground` | `#1F2937` |
| `--card` | `#FFFFFF` |
| `--card-foreground` | `#1F2937` |
| `--primary` | `#1E3A5F` |
| `--primary-foreground` | `#FFFFFF` |
| `--muted-foreground` | `#6B7280` |
| `--border` | `#E7E2DA` |
| `--radius` | `1rem` |

`@theme inline` 블록에 아래 4줄을 추가하고, `--font-sans`는 `var(--font-pretendard)`로 지정합니다.

```css
--color-brand-navy: #1E3A5F;
--color-brand-apricot: #F4A261;
--color-kakao: #FEE500;
--color-kakao-foreground: #191919;
```

- 컴포넌트에서는 `bg-brand-navy`, `text-brand-apricot`, `bg-kakao`처럼 위 변수로 만든 클래스만 씁니다.
- 색의 역할: 이름·제목·주요 강조는 네이비, 배지·단계 번호 같은 포인트는 살구색, 카카오톡 버튼에만 카카오 노란색
- `.dark` 블록은 지우지 않되 사용하지 않습니다. `<html>`에 `dark` 클래스를 붙이지 않습니다.

### 4-2. 디자인 방향 [가이드]

**분위기**: 신뢰감 있으면서 따뜻하게. 은행 앱처럼 차갑지 않고, 여백이 넉넉하며 정돈된 느낌. 장식은 최소로 하고 내용이 잘 읽히는 것을 우선합니다.

아래 기준값을 중심으로 에이전트가 판단해서 정합니다.

| 요소 | 기준값 |
|---|---|
| 콘텐츠 최대 폭 | 480px, 가운데 정렬 **[고정]** |
| 좌우 여백 | 20px 안팎 |
| 섹션 사이 간격 | 넉넉하게 (48px 안팎), 섹션 사이에 shadcn `Separator` 사용 |
| 이름 | 28~32px, 굵게 |
| 섹션 제목 | 20~24px, 반굵게, 네이비 — 모든 섹션이 `SectionHeading` 컴포넌트를 공통으로 사용 **[고정]** |
| 본문 | 16px, 줄 간격 1.6 안팎 |
| 카드 | shadcn `Card`, 둥근 모서리, 옅은 그림자 |
| 주요 버튼 | 화면 폭에 맞춘 넓은 버튼, 높이 48px 이상, 아이콘 + 글자 |
| 배지 | 둥근 알약 모양, 살구색을 옅게 깐 배경 |

### 4-3. 접근성 [고정]

**[고정]** 각 기능의 동작과 완료 기준

| ID | 기능 | 구현 | 완료 기준 |
|---|---|---|---|
| F1 | 카카오톡 상담 | `contact.kakaoChannelUrl`을 새 창으로 여는 링크 (`target="_blank" rel="noopener noreferrer"`) | 휴대폰에서 탭하면 카카오톡 채널 채팅 화면이 열린다 |

미리보기 이미지는 아래를 참고하되, 구성(글자 배치, 장식)은 바꿔도 됩니다.

```tsx
// opengraph-image.tsx
import { ImageResponse } from "next/og";
import { readFile } from "node:fs/promises";
import { join } from "node:path";
import { siteConfig } from "@/config/site";

export const dynamic = "force-static";
export const alt = siteConfig.meta.title;
export const size = { width: 1200, height: 630 };
export const contentType = "image/png";

export default async function OpengraphImage() {
  const font = await readFile(join(process.cwd(), "src/app/fonts/Pretendard-Bold.otf"));
  const { profile } = siteConfig;

  return new ImageResponse(
    (
      <div style={{ width: "100%", height: "100%", display: "flex", flexDirection: "column", justifyContent: "center", padding: "0 80px", background: "#1E3A5F", color: "#FFFFFF", fontFamily: "Pretendard" }}>
        <div style={{ fontSize: 32, color: "#F4A261" }}>{`${profile.title} · ${profile.company}`}</div>
        <div style={{ fontSize: 96, marginTop: 16 }}>{profile.name}</div>
        <div style={{ fontSize: 40, marginTop: 24, opacity: 0.85 }}>{profile.tagline}</div>
      </div>
    ),
    { ...size, fonts: [{ name: "Pretendard", data: font, weight: 700, style: "normal" }] }
  );
}
```

- **필수**: 크기 1200×630, 이름·직함·한 줄 소개 포함, 4-1의 메인 색과 포인트 색만 사용, 폰트는 `Pretendard-Bold.otf` (woff2로는 한글이 깨집니다)
- 카카오톡은 미리보기를 캐시합니다. 배포 후 수정한 미리보기가 반영되지 않으면, 사용자에게 카카오 개발자 사이트의 공유 디버거에서 해당 주소의 캐시를 초기화하도록 안내합니다.

## 10. 초안 이후: 수정·기능 추가 요청 처리 규칙

초안 배포가 끝나면 사용자가 디자인 수정이나 기능 추가를 요청합니다. 이때는 0번 2항("추가하지 않음") 대신 아래 규칙을 따릅니다. 0번의 나머지 규칙(문구는 `site.ts`에만, 막히면 멈추고 보고 등)은 계속 지킵니다.

### 10-1. 요청을 받으면 (순서 고정)
1. **변경 계획 먼저 보여주기** — 코드를 고치기 전에 아래 3가지를 짧게 보여주고 "진행할까요?"라고 묻습니다.
   - 화면에서 무엇이 달라지는지 (한두 문장)
   - 바꾸거나 새로 만들 파일 목록
   - 새로 설치할 것 (없으면 "없음")
2. **요청이 모호하면 먼저 질문하기** — "더 예쁘게", "좀 더 세련되게"처럼 기준이 없는 요청은 고치기 전에 질문 1개로 구체화합니다. (예: "어떤 분위기를 원하시나요? 참고할 이미지가 있으면 첨부해 주세요.")
3. **요청한 범위만 고치기** — 요청하지 않은 문구, 색, 배치, 기능은 건드리지 않습니다.
4. **기준 점검** — 9번의 광고 표현·개인정보 기준에 걸리는 요청은 고치기 전에 알립니다.
5. **마무리** — `npm run lint`와 `npm run build` 통과 → 390×844 스크린샷을 보여주고 확인 받기 → 10-7 형식으로 커밋 → `git push` (Vercel 자동 재배포) → 10-8에 따라 이 문서 갱신

### 10-2. 무엇을 바꾸려면 어디를 고치나

| 바꾸고 싶은 것 | 고칠 곳 |
|---|---|
| 문구, 연락처, 링크 | `site.ts`만 |
| 색상 | 10-3 표의 모든 위치 |
| 글자 크기, 간격, 모서리 | 해당 섹션 컴포넌트의 클래스 (여러 섹션에 공통이면 4-2 기준값도 갱신) |
| 섹션 순서 | `page.tsx`의 순서만 |
| 새 섹션 | 10-4 규칙 |
| 새 기능 | 10-5 규칙 |

### 10-3. 색상 변경 규칙

색은 아래 위치에만 있습니다. 하나의 색을 바꿀 때는 **표에 적힌 모든 위치**를 같은 값으로 함께 바꿉니다.

| 역할 | 현재 값 | 위치 |
|---|---|---|
| 메인 색 | `#1E3A5F` | `globals.css`의 `--primary`, `--color-brand-navy` / `opengraph-image.tsx` 안의 같은 색 / `icon.svg`의 `fill` |
| 포인트 색 | `#F4A261` | `globals.css`의 `--color-brand-apricot` / `opengraph-image.tsx` 안의 같은 색 |
| 배경 색 | `#FAF8F5` | `globals.css`의 `--background` / `layout.tsx`의 `themeColor` |
| 테두리 색 | `#E7E2DA` | `globals.css`의 `--border` |
| 카카오 버튼 | `#FEE500` / `#191919` | 바꾸지 않음 (카카오 브랜드 색) |

- 바꾸기 전에 "역할 / 현재 값 → 새 값" 표를 먼저 보여주고 확인을 받습니다.
- 바꾼 뒤 본문 글자와 배경의 명도 대비가 4.5:1 이상인지 계산해서 결과를 알려줍니다.
- 색을 바꾸면 카카오톡 미리보기 이미지도 바뀌므로, 배포 후 공유 디버거에서 캐시를 초기화하도록 안내합니다.

### 10-4. 섹션 추가 규칙
- 파일: `src/components/sections/(영문 이름).tsx` 하나만 만듭니다.
- 문구: `site.ts`에 새 항목을 추가하고, `sections`에 섹션 제목을 추가합니다.
- 위치: `page.tsx`에서 요청한 위치에 `<Separator />`와 `<Reveal>`로 감싸서 넣습니다.
- 스타일: 4-2 디자인 방향과 기존 섹션의 스타일을 따르고 `SectionHeading`을 재사용하며, `<section>`에 `id`를 붙입니다.
- shadcn/ui 컴포넌트가 필요하면 `npx shadcn@latest add (이름)`으로 추가합니다. 10-1의 계획에 적어 알립니다.

### 10-5. 기능 추가 규칙
- 만들기 전에 6번 표에 새 행(F8, F9, …)을 추가하는 형식으로 **동작과 완료 기준을 먼저 정해서** 보여줍니다.
- npm 패키지 추가는 사용자의 허락을 받은 뒤에만 합니다.
- 서버, 데이터베이스, 외부 서비스 가입이 필요한 기능은 만들지 말고 멈춘 뒤 선택지를 제시합니다. (Static Export 구조 유지)
- 휴대폰에서만 확인할 수 있는 기능은 배포 후 사용자가 확인할 체크리스트를 함께 줍니다.

### 10-6. 되돌리기
- 사용자가 "되돌려줘", "이전으로" 등을 요청하면 `git log --oneline -5`로 최근 기록을 쉬운 말로 보여주고, 어느 시점으로 돌아갈지 확인합니다.
- `git revert`로 되돌립니다. 기록을 지우는 `git reset --hard`는 사용하지 않습니다.
- 되돌린 뒤 `git push`로 배포에도 반영합니다.

### 10-7. 커밋 메시지 형식
- `디자인: (한 줄 설명)` / `기능: (한 줄 설명)` / `문구: (한 줄 설명)` / `오류 수정: (한 줄 설명)`

### 10-8. 이 문서 갱신
- 수정이나 기능 추가를 마칠 때마다 프로젝트 폴더의 `작업지시서.md`에 바뀐 내용을 반영합니다. (색상표, 섹션 명세, 6번 기능 표 등)
- 그래야 새 채팅방에서 이 문서만 첨부해도 현재 상태를 정확히 이어서 작업할 수 있습니다.

### 10-9. 오류를 보고받으면
1. 원인 추정을 쉬운 말로 설명합니다.
2. 원인을 확인하는 방법을 먼저 실행하거나 사용자에게 요청합니다. (확인 없이 여러 곳을 추측으로 고치지 않습니다.)
3. 고칠 방법을 제안하고 승인을 받은 뒤 수정합니다.
4. 같은 증상이 사라졌는지 사용자가 확인할 방법을 알려줍니다.
